# 実務に即した題材の選び方

## 基本ルール
- 題材は「新人が配属先の Web サイト制作・開発の現場で実際に目にしそうな場面」から選ぶ
- 果物・動物・お菓子などの例えや、「田中さん」「山田太郎」のような教科書的な人名は使わない
- 人を表すデータは、実際のシステムのように ID・メールアドレス・権限・所属などで表す
  - 例: `{ userId: "U0001", email: "user0001@example.com", role: "admin", department: "sales" }`
  - メールアドレスは例示用の `@example.com` を使う
- 会社名・商品名は「株式会社テクノロジー」「ノートPC」のように、架空だが実務でありえるものにする
- UI は CLAUDE.md にあるとおり、ボタン操作・モーダル・アコーディオン・タブ切り替え・フォーム入力・一覧表示更新など、Web サイトでよく見るものを題材にする
- ライブデモでは既存の HTML 要素を活用し、新しい素材が必要な場合は事前にユーザーに確認する

## lesson テーマごとの題材例

| lesson | テーマ | 「なぜ必要か」を伝える場面 | 課題の題材例 |
| --- | --- | --- | --- |
| lesson1 | 変数・データ型・演算子 | 消費税率のような同じ値を何か所にも直接書くと、変更時に修正漏れが起きる／フォームの入力値は文字列で届くため、そのまま足すと `"100" + "200"` が `"100200"` になる | 税込価格の計算、会社名・商品名の保存と表示、在庫数の計算 |
| lesson2 | DOM 操作 | 画面の表示内容を、プログラムから書き換えたい | お知らせバナーの文言変更、ログインユーザー名の表示、ステータスバッジの色の切り替え |
| lesson3 | イベント | 「ボタンが押されたとき」「入力されたとき」に処理を動かしたい | 送信ボタン押下で完了メッセージ表示、モーダルの開閉、入力欄の文字数カウント |
| lesson4 | 条件分岐 | 権限や状態によって表示を変えたい | 管理者だけに編集ボタンを表示、在庫 0 なら「売り切れ」表示、送料無料ラインの判定、入力チェックのエラー表示 |
| lesson5 | ループ | 件数が変わるデータを、1 件ずつ同じ処理で扱いたい | 通知一覧の表示、カート内商品の合計金額、複数カードへの一括処理 |
| lesson6 | 配列 | 一覧データをまとめて扱い、絞り込み・並び替えたい | 注文一覧から未発送だけ表示、商品の価格順並び替え、検索結果の件数表示 |
| lesson7 | 関数 | 同じ処理を画面のあちこちにコピペしている | 税込価格の計算関数、メールアドレスの入力チェック関数、日付の表示形式をそろえる関数 |

## 提出課題・総合演習を実務に近づけるコツ
- 課題文の書き方（「何を実現するか」のみ・断定形・クォートの使い分け）は CLAUDE.md の「課題文の記載ルール」を守る。形式は変えず、**題材（シナリオ・データ・画面）を実務に寄せる**
- データは実務でありえる項目と件数にする（例: 注文データに `orderId`・`productName`・`price`・`quantity`・`status` を持たせ、3〜5 件用意する）
- 総合演習は「小さな機能を 1 つ作りきる」形にする（例: 注文データから小計・消費税・送料・請求金額を計算して画面に表示する）
- 「少し調べないと解けない要素」は、レッスンで教えた内容の 1 歩先にする（例: 配列の絞り込みを教えた → 課題では並び替えも必要）

## 新しい題材を考えるときのチェック
- その場面は、実際の開発現場で本当に起きるか
- 受講者が知らない業務知識（会計・金融の専門知識など）が必要になっていないか
- 業務の説明が長くなりすぎて、教えたい概念がぼやけていないか
